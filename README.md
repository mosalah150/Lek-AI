# Lek-AI: ชุดติดตั้ง Local AI สำหรับทีมขนาดเล็ก

ชุดติดตั้ง AI ที่รันในบ้านหรือองค์กรเองบน workstation ที่มี GPU พร้อม NAS สำหรับ backup ข้อมูลลับไม่ออกนอกองค์กร ใช้งานได้ไม่จำกัด และออกแบบมาให้คนที่ถนัด Windows ติดตั้งและดูแลได้ **โดยไม่ต้องใช้ Docker**

| | |
|---|---|
| **เหมาะกับ** | 1–10 คน (ใช้พร้อมกัน 2–3 คน) |
| **ระบบปฏิบัติการ** | Windows 11 Pro |
| **ติดตั้ง** | สคริปต์ PowerShell คำสั่งเดียว |
| **ดูแลระบบ** | Remote Desktop + คำสั่งลัด `ai` |
| **ค่าใช้จ่ายต่อเดือน** | ค่าไฟประมาณ 400–700 บาท (ถ้ามีฮาร์ดแวร์อยู่แล้ว) |
| **📘 คู่มือติดตั้งและใช้งาน** | [docs/install.md](docs/install.md) (ภาษาไทย ทีละขั้น) |
| **🌐 คู่มือเครือข่าย (ตัวเลือก: กรณีไม่มีสาย LAN ถึง router)** | [docs/network-mikrotik.md](docs/network-mikrotik.md) (MikroTik hAP ac² เป็น Wi-Fi client) |

---

## 1. สิ่งที่ชุดนี้ทำให้

1. **ถามตอบจากเอกสารภายใน (RAG):** อัปโหลด PDF, Word หรือ Excel แล้วถามได้เลย พร้อมแบ่งสิทธิ์ตามกลุ่มผู้ใช้
2. **แชทและร่างเอกสาร:** ใช้กับข้อมูลลับได้ เพราะทุกอย่างประมวลผลในเครื่อง
3. **จัดการโมเดลผ่านหน้าจอ:** ค้นหา ดาวน์โหลด และทดลองโมเดลใน LM Studio ไม่ต้องพิมพ์คำสั่ง
4. **สร้างภาพ วิดีโอ และ asset เกมด้วย ComfyUI (ตัวเลือก)**
5. **เข้าใช้จากข้างนอกอย่างปลอดภัย:** ผ่าน Tailscale โดยไม่ต้องเปิดพอร์ตบน router พร้อม HTTPS ที่ถูกต้อง
6. **Backup อัตโนมัติทุกคืน:** ไปที่ NAS พร้อมรับมือไฟดับ

**สิ่งที่ไม่ได้ทำ:** ไม่ได้มาแทน AI บน cloud (เช่น Claude) ในงานที่ต้องการความฉลาดสูงสุด แนะนำให้ใช้ทั้งสองอย่างคู่กัน (ดูหัวข้อ 5)

## 2. ฮาร์ดแวร์อ้างอิง

ชุดนี้ออกแบบสำหรับฮาร์ดแวร์ด้านล่าง ถ้าใช้เครื่องอื่นที่มี NVIDIA GPU และ VRAM 16GB ขึ้นไป ก็ปรับใช้ได้

| อุปกรณ์ | สเปก | บทบาท |
|---|---|---|
| **Dell Precision 5820** | i9-10980XE 18C/36T · RAM 128GB · Quadro RTX 6000 24GB · NVMe 1TB · HDD 2TB | **AI Server:** GPU รันโมเดล ส่วน CPU ใช้ทำ embedding ของเอกสาร |
| **Synology DS918+** | 4-Bay · RAID5 | **Storage:** เก็บเอกสาร รับ backup และทำ Snapshot |
| **MikroTik hAP ac²** (ตัวเลือก) | — | รับเน็ตผ่าน Wi-Fi แล้วปล่อย LAN ให้ server และ NAS ในกรณีที่ไม่มีสายระหว่างชั้น |
| **เครื่องของผู้ดูแล** | Mac หรือ PC | ใช้งานและจัดการ server ผ่าน Remote Desktop และ Tailscale |

## 3. สถาปัตยกรรม

```
 ผู้ใช้ใน LAN ─────────────┐        ผู้ดูแล (นอกบ้าน) ── Tailscale VPN ──┐
                          ▼                                         ▼
┌──────────── AI Server · Windows 11 Pro (ไม่ใช้ Docker) ─────────────────────┐
│  Open WebUI :3000 ── หน้าแชท, ถามตอบเอกสาร (RAG), บัญชีผู้ใช้, API key          │
│        │             embedding bge-m3 + reranker (บน CPU)                    │
│        └─► LM Studio :1234 (เฉพาะในเครื่อง) ── Qwen3 30B, Qwen3 Coder (GPU)    │
│  ComfyUI Desktop (ตัวเลือก) ── สร้างภาพ / วิดีโอ (ใช้ GPU ร่วมกัน)              │
│  Remote Desktop ── จัดการเครื่องจาก Mac หรือ PC                               │
└────────────────────────────────────┬────────────────────────────────────────┘
                                     │ SMB · backup ทุกคืน
                       NAS (Synology) : ai-docs · ai-backup · Snapshot
```

### หลักการทำงานของการถามตอบเอกสาร (RAG)
1. **อัปโหลดเอกสาร (ทำครั้งเดียว):** Open WebUI แปลงเอกสารเป็นข้อความ ตัดเป็นท่อน แล้ว bge-m3 แปลงความหมายเป็นตัวเลขเก็บใน vector DB
2. **ถามคำถาม (ทุกครั้ง):** ระบบค้นท่อนที่เกี่ยวข้อง (ทั้งค้นจากความหมายและจากคำตรงตัว) ให้ reranker คัดท่อนที่ตรงที่สุด แล้วส่งให้ LLM ตอบพร้อมอ้างอิงแหล่งที่มา
3. ผู้ใช้จะเห็นเฉพาะเอกสารใน Knowledge ที่กลุ่มของตัวเองมีสิทธิ์

## 4. การตัดสินใจหลักและเหตุผล

| เรื่อง | เลือก | เหตุผล | ทางเลือกที่พิจารณาแล้ว |
|---|---|---|---|
| ระบบปฏิบัติการ | **Windows 11 Pro** | ผู้ดูแลถนัด Windows, ใช้ LM Studio และ ComfyUI ผ่านหน้าจอได้ | Ubuntu (ชุดติดตั้งอยู่ที่ `_ubuntu-version/`): ดูแลแบบ server ง่ายกว่า แต่ต้องใช้ command line |
| Docker | **ไม่ใช้** | ไม่ติดเงื่อนไข license ของ Docker Desktop, ไม่เสีย RAM ให้ WSL2, ทุกอย่างเป็นโปรแกรม Windows ปกติ | Docker Desktop (ต้องดูแลสองชั้น) |
| เครื่องยนต์ LLM | **LM Studio** | จัดการโมเดลผ่านหน้าจอ เห็นการใช้ VRAM, มี API แบบ OpenAI, รองรับ MCP | Ollama (ใช้คำสั่ง), vLLM (เกินความจำเป็นสำหรับทีมเล็ก) |
| หน้าใช้งาน | **Open WebUI** (ติดตั้งผ่าน Python) | มีครบทั้งแชท RAG บัญชีผู้ใช้ กลุ่ม และ API key | หน้าแชทของ LM Studio (ใช้ได้คนเดียว ต้อง Remote Desktop เข้าไป) |
| เข้าใช้จากข้างนอก | **Tailscale** | ไม่ต้องเปิดพอร์ต ใช้ได้แม้อยู่หลัง CGNAT ได้ HTTPS ที่ถูกต้อง และข้อมูลไม่ผ่านตัวกลาง | Cloudflare Tunnel (ทราฟฟิกผ่าน Cloudflare) |
| เริ่มทำงานหลังบูต | **Task Scheduler + Autologon** | Open WebUI เริ่มเองโดยไม่ต้องล็อกอิน ส่วน LM Studio ต้องให้ Windows ล็อกอินเอง | Windows Service (ซับซ้อนกว่าสำหรับมือใหม่) |
| งานอัตโนมัติ | **ยังไม่ติดตั้ง** | เริ่มให้ระบบเรียบง่ายก่อน | n8n (ติดตั้งเพิ่มได้ภายหลังผ่าน Node.js) |

## 5. Local AI หรือ AI บน cloud: ใช้อะไรกับงานไหน

**กฎหลัก:** 🔒 ข้อมูลลับหรือข้อมูลส่วนบุคคลใช้ Local เท่านั้น · ☁️ งานยากที่ข้อมูลไม่ลับใช้ AI บน cloud (เช่น Claude)

| บทบาท | 🔒 Local AI | ☁️ AI บน cloud |
|---|---|---|
| **Product / Project Manager** | ถอดเสียงและสรุปประชุม, ถามตอบ spec ภายใน, วิเคราะห์ข้อมูล ticket ปริมาณมาก | เขียน PRD, วางกลยุทธ์ roadmap |
| **Marketing** | สร้างภาพโซเชียลและแบนเนอร์, caption หลายสิบแบบ, วิเคราะห์ sentiment, ซับไตเติล | copy เชิงสร้างสรรค์, วางแผนแคมเปญ |
| **IT / Ops** | สรุป log, ตรวจ config, helpdesk bot, คัดแยก ticket/alert, สคริปต์ขนาดเล็ก | ออกแบบระบบ, ไล่บั๊กที่ซับซ้อน |
| **Creative / พัฒนาเกม** | sprite, texture, concept art, เสียงประกอบ, NPC ที่คุยได้ | เขียนโค้ด |
| **ทุกคน** | ถามตอบเอกสาร (HR, SOP, คู่มือ), ร่างเอกสารจากข้อมูลภายใน | งานวิเคราะห์ที่ต้องคิดหลายขั้น |

> **ข้อจำกัดของ Local AI:** โมเดลขนาด ~30B บนการ์ด 24GB เขียนโค้ดงานใหญ่และคิดซับซ้อนได้ด้อยกว่า AI ระดับแนวหน้าบน cloud ชัดเจน และไม่รู้ข้อมูลหลังวันที่โมเดลถูกเทรน

## 6. ความปลอดภัย

- **ไม่เปิดพอร์ตใดๆ บน router:** การเข้าจากข้างนอกทั้งหมดผ่าน Tailscale
- **LM Studio และ ComfyUI ไม่มีระบบล็อกอิน:** LM Studio รับเฉพาะในเครื่อง และ firewall ปิดพอร์ต 1234 ไว้อีกชั้น ส่วน ComfyUI เปิดเฉพาะผ่าน Tailscale
- **แบ่งสิทธิ์เอกสาร:** Knowledge แยกตามกลุ่ม ผูกกับ Group ใน Open WebUI
- **รหัสลับ:** `install.ps1` สุ่มให้อัตโนมัติ เก็บที่ `C:\ai\config.json` (เฉพาะ admin อ่านได้) ไม่มีรหัสลับใดอยู่ใน repo นี้
- **Remote Desktop:** ใช้รหัสผ่าน Windows ที่แข็งแรง และเข้าจากข้างนอกผ่าน Tailscale เท่านั้น
- **ถ้าเชื่อม AI บน cloud เข้า Open WebUI:** ห้ามผูก Knowledge ที่เป็นความลับกับโมเดลภายนอก เพราะระบบจะส่งท่อนเอกสารออกไปด้วย

## 7. Backup และการรับมือไฟดับ

| ข้อมูล | ต้นฉบับ | สำเนา |
|---|---|---|
| แชท, ผู้ใช้, Knowledge, ค่าตั้ง | `C:\ai` บน NVMe | NAS `ai-backup` ทุกคืน (เก็บ 14 วัน) + Snapshot ของ NAS |
| เอกสาร | NAS `ai-docs` | HDD ของ server ทุกคืน + Snapshot ของ NAS |
| โมเดล | LM Studio บน NVMe | ไม่ต้อง backup เพราะดาวน์โหลดใหม่ได้ |

**กรณีไม่มี UPS:** BIOS ตั้งให้ server เปิดเองเมื่อไฟกลับมา, Autologon ทำให้ LM Studio เริ่มเอง, Open WebUI เริ่มเองตอนบูต, NAS ตั้งให้เปิดเองเช่นกัน และ backup จะไม่ทำงานถ้าเข้าถึง NAS ไม่ได้ อย่างไรก็ตาม แนะนำให้มี UPS ขนาด 1000VA ขึ้นไป

## 8. แผนนำร่องที่แนะนำ

| ระยะ | ช่วงเวลา | งาน | วัดผลสำเร็จ |
|---|---|---|---|
| **0. ติดตั้ง** | สัปดาห์ที่ 1 | ติดตั้ง Windows, `install.ps1`, LM Studio, NAS + backup, ทดสอบกู้คืน | `ai status` ปกติ, backup ขึ้น `OK`, กู้คืนได้จริง |
| **1. นำร่อง** | สัปดาห์ที่ 2–3 | ผู้ใช้ 1–5 คน: ถามตอบเอกสาร + สรุปงาน | ประหยัดเวลา ≥2–3 ชั่วโมงต่อคนต่อสัปดาห์ และคำตอบอ้างอิงเอกสารถูก ≥80% |
| **2. ขยาย** | เดือนที่ 2 | เพิ่มผู้ใช้, ComfyUI สำหรับ content | มีคนใช้งานจริงทุกสัปดาห์ |
| **3. ต่อยอด** | เดือนที่ 3 ขึ้นไป | n8n (LINE bot, โพสต์ Facebook), MCP เชื่อม Claude, UPS | ตามความต้องการ |

**จุดตัดสินใจหลังนำร่อง:** ถ้าประหยัดเวลาได้ไม่ถึงเป้า ให้ปิดระบบแล้วใช้ AI บน cloud อย่างเดียว

## 9. ความเสี่ยงที่ควรรู้

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| ไฟดับ (กรณีไม่มี UPS) | RAID ของ NAS และข้อมูลเสียหาย | เปิดเครื่องเองเมื่อไฟกลับ, Snapshot, จัดหา UPS |
| Windows Update รีสตาร์ตเอง | ระบบดับกลางวัน | `install.ps1` ตั้ง policy ไม่ให้รีสตาร์ตเองขณะมีคนล็อกอิน และ Autologon ทำให้ล็อกอินเสมอ |
| Server มีเครื่องเดียว | ถ้าเครื่องเสีย ระบบหยุดทั้งหมด | backup ทุกคืน ติดตั้งใหม่ด้วย `install.ps1` แล้วกู้ข้อมูลตามคู่มือ |
| AI ตอบผิด | ตัดสินใจผิด | ให้ AI อ้างอิงเอกสารทุกครั้ง และไม่ให้ AI ตัดสินใจแทนคนโดยไม่มีคนตรวจ |
| อัปเดตแล้วระบบเสีย | ใช้งานไม่ได้ชั่วคราว | `ai update` จะ backup ก่อนทุกครั้ง |

## 11. เริ่มต้นอย่างรวดเร็ว

บน server ที่ติดตั้ง Windows 11 Pro แล้ว ดาวน์โหลด ZIP ของ repo นี้แตกไว้ที่ `C:\Lek-AI` แล้วเปิด **Terminal (Admin)**:

```powershell
cd C:\Lek-AI
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install.ps1          # ติดตั้งทั้งระบบ
.\scripts\setup-backup.ps1     # เชื่อม NAS และตั้ง backup
ai status                      # ตรวจว่าระบบปกติ (เปิด Terminal ใหม่ก่อน)
```

จากนั้นตั้งค่า LM Studio และ Autologon ตาม **[docs/install.md](docs/install.md)**

> ⚠️ ชุดติดตั้งนี้ยังไม่ได้ทดสอบครบทุกขั้นบนเครื่องจริง ชื่อรุ่นโมเดลและเมนูของโปรแกรมอาจเปลี่ยนไปตามเวลา ถ้าพบปัญหา เปิด Issue ได้เลย
