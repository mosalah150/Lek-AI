# Lek-AI: ชุดติดตั้ง Local AI สำหรับทีมขนาดเล็ก

ชุดติดตั้ง AI ที่รันในองค์กรเองบน workstation ที่มี GPU พร้อม NAS สำหรับ backup ข้อมูลลับไม่ออกนอกองค์กร ใช้งานได้ไม่จำกัด และออกแบบมาให้คนที่ไม่ถนัด Linux ติดตั้งและดูแลได้

| | |
|---|---|
| **เหมาะกับ** | ทีมราว 10 คน (ใช้พร้อมกัน 2–3 คน) |
| **ติดตั้ง** | สคริปต์คำสั่งเดียวบน Ubuntu Server 24.04 |
| **ดูแลระบบ** | คำสั่งลัด `ai` + หน้าเว็บ Cockpit |
| **ค่าใช้จ่ายต่อเดือน** | ค่าไฟประมาณ 400–700 บาท (ถ้ามีฮาร์ดแวร์อยู่แล้ว) |
| **📘 คู่มือติดตั้งและใช้งาน** | [docs/install.md](docs/install.md) (ภาษาไทย ทีละขั้น) |
| **🌐 คู่มือเครือข่าย (กรณีไม่มีสาย LAN ระหว่างชั้น)** | [docs/network-mikrotik.md](docs/network-mikrotik.md) (MikroTik hAP ac² เป็น Wi-Fi client) |

---

## 1. สิ่งที่ชุดนี้ทำให้

1. **ถามตอบจากเอกสารภายใน (RAG):** อัปโหลด PDF, Word หรือ Excel แล้วถามได้เลย พร้อมแบ่งสิทธิ์ตามแผนก
2. **แชทและร่างเอกสาร:** ใช้กับข้อมูลลับได้ เพราะทุกอย่างประมวลผลในเครื่อง
3. **งานอัตโนมัติด้วย n8n:** เช่น สรุปอีเมลหรือ log ทุกเช้าแล้วส่งเข้าแชท
4. **สร้างภาพ เสียง และ 3D ด้วย ComfyUI (ตัวเลือก):** สำหรับงาน marketing หรือ asset เกม
5. **เข้าใช้จากข้างนอกอย่างปลอดภัย:** ผ่าน Tailscale โดยไม่ต้องเปิดพอร์ตบน router
6. **Backup อัตโนมัติทุกคืน:** ไปที่ NAS พร้อมรับมือไฟดับ

**สิ่งที่ไม่ได้ทำ:** ไม่ได้มาแทน AI บน cloud (เช่น Claude) ในงานที่ต้องการความฉลาดสูงสุด แนะนำให้ใช้ทั้งสองอย่างคู่กัน (ดูหัวข้อ 5)

## 2. ฮาร์ดแวร์อ้างอิง

ชุดนี้ออกแบบสำหรับฮาร์ดแวร์ด้านล่าง ถ้าใช้เครื่องอื่นที่มี NVIDIA GPU และ VRAM 16GB ขึ้นไป ก็ปรับใช้ได้

| อุปกรณ์ | สเปก | บทบาท |
|---|---|---|
| **Dell Precision 5820** | i9-10980XE 18C/36T · RAM 128GB · Quadro RTX 6000 24GB · NVMe 1TB · HDD 2TB | **AI Server:** GPU ประมวลผลโมเดล ส่วน CPU และ RAM ใช้แปลงเอกสารและช่วยรันโมเดลใหญ่ |
| **Synology DS918+** | 4-Bay · RAID5 | **Storage:** เก็บเอกสารต้นทาง รับ backup และทำ Snapshot |
| **เครื่องของผู้ดูแล** | Mac, Windows หรือ Linux | ใช้งานและจัดการ server ผ่าน SSH, Cockpit และ Tailscale |

## 3. สถาปัตยกรรม

```
 ผู้ใช้ใน LAN ─────────────┐        ผู้ดูแล (นอกออฟฟิศ) ── Tailscale VPN ──┐
                          ▼                                          ▼
┌──────────── AI Server · Ubuntu Server 24.04 · Docker ───────────────────────┐
│  Open WebUI :3000 ── หน้าแชท, ถามตอบเอกสาร (RAG), บัญชีผู้ใช้, API key           │
│        │                                                                    │
│        ├─► Ollama (GPU) ──── LLM: Qwen3-30B-A3B, Qwen3-Coder, bge-m3        │
│        └─► Docling (CPU) ─── แปลง PDF / ตาราง / OCR                         │
│  n8n :5678 + PostgreSQL ──── งานอัตโนมัติ (เรียก Ollama ภายใน)                │
│  ComfyUI (ตัวเลือก) ──────── สร้างภาพ / เสียง / 3D (ใช้ GPU ร่วมกัน)             │
│  Cockpit :9090 ──────────── จัดการเครื่องผ่านหน้าเว็บ                           │
└────────────────────────────────────┬────────────────────────────────────────┘
                                     │ NFS · backup ทุกคืน
                       NAS (Synology) : ai-docs · ai-backup · Snapshot
```

### หลักการทำงานของการถามตอบเอกสาร (RAG)
1. **อัปโหลดเอกสาร (ทำครั้งเดียว):** Docling แปลงเป็นข้อความ แล้วตัดเป็นท่อน จากนั้น bge-m3 แปลงความหมายเป็นตัวเลขเก็บใน vector DB
2. **ถามคำถาม (ทุกครั้ง):** ระบบค้นท่อนเอกสารที่เกี่ยวข้อง 3–5 ท่อน แนบให้ LLM อ่าน แล้วตอบพร้อมอ้างอิงแหล่งที่มา
3. ผู้ใช้จะเห็นเฉพาะเอกสารใน Knowledge ที่กลุ่มของตัวเองมีสิทธิ์

## 4. การตัดสินใจหลักและเหตุผล

| เรื่อง | เลือก | เหตุผล | ทางเลือกที่พิจารณาแล้ว |
|---|---|---|---|
| ระบบปฏิบัติการ | **Ubuntu Server 24.04** | เป็น server เปิดทิ้งไว้ ไม่มีปัญหาอัปเดตแล้วรีสตาร์ตเอง ใช้ RAM ได้เต็ม และ license ฟรี | Windows 11 (มีชุดติดตั้งที่ `_windows-version/`) ต้องตั้ง Autologon และอาจติดเงื่อนไข license ของ Docker Desktop |
| เครื่องยนต์ LLM | **Ollama** | ติดตั้งง่าย สลับโมเดลอัตโนมัติ เสถียรบนการ์ดรุ่น Turing | vLLM (เกินความจำเป็นสำหรับทีมเล็ก), llama.cpp โดยตรง (ต้องตั้งค่าเอง) |
| หน้าใช้งาน | **Open WebUI** | มีครบทั้งแชท RAG บัญชีผู้ใช้ กลุ่ม และ API key | LibreChat, AnythingLLM |
| เข้าใช้จากข้างนอก | **Tailscale** | ไม่ต้องเปิดพอร์ต ใช้ได้แม้อยู่หลัง CGNAT และข้อมูลไม่ผ่านตัวกลาง | Cloudflare Tunnel (ทราฟฟิกผ่าน Cloudflare) |
| บัญชีผู้ใช้ | **บัญชีภายใน Open WebUI** | ไม่ต้องมีระบบ SSO, admin อนุมัติผู้สมัครเอง | AD/LDAP, Google/Microsoft SSO (ทำเพิ่มได้ภายหลัง) |
| Vector DB | **ตัวในของ Open WebUI** | เหมาะกับเอกสารจำนวนไม่มาก ลดจำนวนชิ้นส่วนที่ต้องดูแล | Qdrant (ย้ายเมื่อเอกสารเกินราวหมื่นไฟล์) |

## 5. Local AI หรือ AI บน cloud: ใช้อะไรกับงานไหน

**กฎหลัก:** 🔒 ข้อมูลลับหรือข้อมูลส่วนบุคคลใช้ Local เท่านั้น · ☁️ งานยากที่ข้อมูลไม่ลับใช้ AI บน cloud (เช่น Claude)

| บทบาท | 🔒 Local AI | ☁️ AI บน cloud |
|---|---|---|
| **Product / Project Manager** | ถอดเสียงและสรุปประชุม, ถามตอบ spec ภายใน, วิเคราะห์ข้อมูล ticket ปริมาณมาก | เขียน PRD, วางกลยุทธ์ roadmap |
| **Marketing** | สร้างภาพโซเชียลและแบนเนอร์, caption หลายสิบแบบ, วิเคราะห์ sentiment, ซับไตเติล | copy เชิงสร้างสรรค์, วางแผนแคมเปญ |
| **IT / Ops** | สรุป log, ตรวจ config, helpdesk bot, คัดแยก ticket/alert, สคริปต์ขนาดเล็ก | ออกแบบระบบ, ไล่บั๊กที่ซับซ้อน |
| **Creative / พัฒนาเกม** | sprite, texture, concept art, เสียงประกอบ, โมเดล 3D, NPC ที่คุยได้ | เขียนโค้ด |
| **ทุกคน** | ถามตอบเอกสารบริษัท (HR, SOP, คู่มือ), ร่างเอกสารจากข้อมูลภายใน | งานวิเคราะห์ที่ต้องคิดหลายขั้น |

> **ข้อจำกัดของ Local AI:** โมเดลขนาด ~30B บนการ์ด 24GB เขียนโค้ดงานใหญ่และคิดซับซ้อนได้ด้อยกว่า AI ระดับแนวหน้าบน cloud ชัดเจน และไม่รู้ข้อมูลหลังวันที่โมเดลถูกเทรน

## 6. ความปลอดภัย

- **ไม่เปิดพอร์ตใดๆ บน router:** การเข้าจากข้างนอกทั้งหมดผ่าน Tailscale
- **Ollama และ ComfyUI ไม่มีระบบล็อกอิน:** Ollama เปิดเฉพาะภายใน Docker ส่วน ComfyUI เปิดเฉพาะผ่าน Tailscale
- **แบ่งสิทธิ์เอกสาร:** Knowledge แยกตามแผนก ผูกกับ Group ใน Open WebUI
- **รหัสลับ:** `setup.sh` สุ่มให้อัตโนมัติบน server เก็บที่ `/opt/ai/stack/.env` ไม่มีรหัสลับใดอยู่ใน repo นี้
- **ถ้าเชื่อม AI บน cloud เข้า Open WebUI:** ห้ามผูก Knowledge ที่เป็นความลับกับโมเดลภายนอก เพราะระบบจะส่งท่อนเอกสารออกไปด้วย

## 7. Backup และการรับมือไฟดับ

| ข้อมูล | ต้นฉบับ | สำเนา |
|---|---|---|
| แชท, ผู้ใช้, Knowledge, workflow n8n, config | NVMe ของ server | NAS `ai-backup` ทุกคืน (เก็บ 14 วัน) + Snapshot ของ NAS |
| เอกสาร | NAS `ai-docs` | HDD ของ server ทุกคืน (เก็บ 30 วัน) + Snapshot ของ NAS |
| โมเดล | NVMe | ไม่ต้อง backup เพราะดาวน์โหลดใหม่ได้ |

**กรณีไม่มี UPS:** คู่มือตั้งให้ server และ NAS เปิดเองเมื่อไฟกลับมา บริการทุกตัวกลับมาเอง NAS ปิด write cache และ backup จะไม่ทำงานถ้า NAS ไม่ได้เชื่อมต่อ อย่างไรก็ตาม แนะนำให้มี UPS ขนาด 1000VA ขึ้นไป

## 8. แผนนำร่องที่แนะนำ

| ระยะ | ช่วงเวลา | งาน | วัดผลสำเร็จ |
|---|---|---|---|
| **0. ติดตั้ง** | สัปดาห์ที่ 1 | ติดตั้ง Ubuntu, `setup.sh`, NAS + backup, ทดสอบกู้คืน | `ai status` ปกติ, backup ขึ้น `OK`, กู้คืนได้จริง |
| **1. นำร่อง** | สัปดาห์ที่ 2–3 | ผู้ใช้ 3–5 คน: ถามตอบเอกสาร + สรุปประชุม | ประหยัดเวลา ≥2–3 ชั่วโมงต่อคนต่อสัปดาห์ และคำตอบอ้างอิงเอกสารถูก ≥80% |
| **2. ขยาย** | เดือนที่ 2 | เปิดให้ทั้งทีม, workflow n8n ตัวแรก, ComfyUI | มีคนใช้งานจริงทุกสัปดาห์ ≥70% ของทีม |
| **3. ต่อยอด** | เดือนที่ 3 ขึ้นไป | เชื่อม AI บน cloud, Qdrant, SSO, UPS | ตามความต้องการ |

**จุดตัดสินใจหลังนำร่อง:** ถ้าประหยัดเวลาได้ไม่ถึงเป้า ให้ปิดระบบแล้วใช้ AI บน cloud อย่างเดียว

## 9. ความเสี่ยงที่ควรรู้

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| ไฟดับ (กรณีไม่มี UPS) | RAID ของ NAS และข้อมูลเสียหาย | เปิดเครื่องเองเมื่อไฟกลับ, ปิด write cache, Snapshot, จัดหา UPS |
| Server มีเครื่องเดียว | ถ้าเครื่องเสีย ระบบหยุดทั้งหมด | backup ทุกคืน ติดตั้งใหม่ด้วย `setup.sh` แล้วกู้ข้อมูลได้ |
| ผู้ดูแลไม่คุ้นกับ Linux | แก้ปัญหาช้า | สคริปต์อัตโนมัติ, คำสั่ง `ai`, Cockpit, ตารางแก้ปัญหาในคู่มือ |
| AI ตอบผิด | ตัดสินใจผิด | ให้ AI อ้างอิงเอกสารทุกครั้ง และไม่ให้ AI ตัดสินใจแทนคนโดยไม่มีคนตรวจ |
| อัปเดตแล้วระบบเสีย | ใช้งานไม่ได้ชั่วคราว | `ai update` จะ backup ก่อนทุกครั้ง และควร pin เวอร์ชันของ image |

## 10. โครงสร้าง repo

```
Lek-AI/
├── README.md                  ← ภาพรวม (ไฟล์นี้)
├── docs/install.md            ← คู่มือติดตั้งและใช้งานทีละขั้น (มือใหม่ทำตามได้)
├── docs/network-mikrotik.md   ← คู่มือเครือข่าย: MikroTik เป็น Wi-Fi client ปล่อย LAN ให้ server/NAS
├── setup.sh                   ← ติดตั้งทั้งระบบด้วยคำสั่งเดียว
├── ai                         ← คำสั่งลัดสำหรับดูแลระบบ (ai status, ai update ...)
├── docker-compose.yml         ← Ollama, Open WebUI, Docling, n8n, PostgreSQL
├── scripts/
│   ├── setup-backup.sh        ← เชื่อม NAS และตั้ง backup อัตโนมัติ
│   ├── backup-to-nas.sh       ← backup ข้อมูลระบบไป NAS (ทุกคืน 02:00)
│   ├── mirror-nas-docs.sh     ← สำรองเอกสารจาก NAS ลง HDD (ทุกคืน 02:30)
│   └── install-comfyui.sh     ← (ตัวเลือก) ติดตั้ง ComfyUI
└── _windows-version/          ← ชุดติดตั้งทางเลือกสำหรับ Windows 11
```

## 11. เริ่มต้นอย่างรวดเร็ว

```bash
ssh user@<IP-ของ-server>
cd ~/local-ai && sudo bash setup.sh      # รัน 2 รอบ (รีสตาร์ตคั่นหลังติดตั้ง driver)
sudo bash scripts/setup-backup.sh        # เชื่อม NAS และตั้ง backup
ai status                                # ตรวจว่าระบบปกติ
```

รายละเอียดทุกขั้นตอน ตั้งแต่ทำ USB ติดตั้ง Ubuntu อยู่ใน **[docs/install.md](docs/install.md)**

> ⚠️ ชุดติดตั้งนี้ยังไม่ได้ทดสอบครบทุกขั้นบนเครื่องจริง ชื่อรุ่นโมเดลและ image อาจเปลี่ยนไปตามเวลา ถ้าพบปัญหา เปิด Issue ได้เลย
